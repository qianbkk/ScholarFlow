Reviewed: 1 commit (R10.5.38 v4 focus-first rewrite, 27 files, +1622/-1008) + uncommitted R10.5.39 multi-source searcher work (3 new backend clients + 1 modified agent + 1 new test, ~880 lines net new). Cumulative +~2500/-~1100 lines.

## Headline

R10.5.38 delivered the v4 focus-first rewrite cleanly: the 9 new ui/ components share
sane styles and the new state machine (`empty | running | done | error`) is much easier
to reason about than v3's three-column layout. The uncommitted R10.5.39 multi-source
work (arxiv/crossref/pubmed clients + search_agent integration) is functionally correct
but is **the highest-debt part of the diff** — 3 new clients ship with ~250 LOC of
duplicated throttle/HTTP/parse boilerplate that the codebase already has helpers for,
plus a `source="openalex"` placeholder hack that will silently mis-classify the new
sources in any frontend filter. On the v4 frontend side, two real correctness bugs
are hiding in the new code (D3 hover highlight breaks after first tick; compare-mode
trigger fails when paper is already in selected set) and two user-visible behaviors
were removed without replacement (`is_degraded` indicator; live SSE event log channel).

## Pass 1: /simplify findings (cleanup, ranked)

1. **`backend/api/{arxiv,crossref,pubmed}.py` + `search_agent.py`** — Three new API clients re-implement HTTP fetch + retry + throttle + parse boilerplate instead of reusing `backend/api/_retry.py::_get_with_retry` (4-attempt exponential backoff, 429/Retry-After, circuit-breaker integration), `backend/api/semantic_scholar.py::_get_client()` (module-level AsyncClient singleton), and `backend/utils/circuit_breaker.py::CircuitBreaker` already used by SS/OA. Each client also re-implements a 3-line throttle triplet (`_X_LOCK` / `_LAST_X_TS` / `_throttle_x()`). Cost: ~90 LOC duplicated fetch+retry+throttle + 3 independent TCP/TLS pool rebuilds per request (the exact leak class the SS/OA `_DISABLE_POOL` fix solved) + transient 503s silently dropped instead of breaker-recorded. Fix: extract `backend/api/_base.py` with `throttle(seconds)`, `safe_get(client, url, params, label)`, and `mock_skip()`; wire all 3 clients through `_get_with_retry` + module-level `AsyncClient` + named breakers.
2. **`backend/api/{arxiv.py:84, crossref.py:97, pubmed.py:123}`** — All three new clients set `source="openalex"` with the comment "reuse enum slot; frontend filters by source". The Paper model has no source Literal/enum, so this works syntactically but the frontend filter that distinguishes SS vs OA vs arXiv vs Crossref vs PubMed will silently mis-classify all three new sources as OpenAlex. Cost: filter correctness broken the day a consumer reads by source. Fix: widen `Paper.source` to `Literal["ss","oa","arxiv","crossref","pubmed"]` and set the real name in each `_make_paper`.
3. **`newversion/frontend/src/ui/ReportView.tsx:22,33-47,93`** — Outer component declares `const [, setHtml] = useState('')` and a `useEffect` that runs `marked.parse` + `DOMPurify.sanitize` + `paper_id` regex but **never renders the result** — line 93 is `<div dangerouslySetInnerHTML={{ __html: '' }} />` (permanently empty). The inner `RenderMarkdown` component does the same parse/sanitize/regex pipeline again. Cost: 2× markdown parse + sanitize per render (real cost, citations are non-trivial) + 25 LOC duplicated + a confusing `useState` that's only kept in sync with itself. Fix: delete the outer `useEffect` + `setHtml` + empty div; lift `parse(markdown, lookup)` into a single `useMemo`.
4. **`newversion/frontend/src/App.tsx:17-37,79-140`** — `Modal` takes a `size?: 'full' | 'drawer'` prop and all 3 callers pass it, but the render body never reads it (always renders `fixed inset-0 z-30`). The drawer case (PapersDrawer) escapes the shell entirely and hand-rolls `fixed inset-y-0 right-0 w-[400px]`. The graph modal inlines its own 47-line header chrome (hairline-b + mono labels + esc close button) with 3 inline `style={{ background: 'var(--base)' }}` overrides. Cost: 3 places disagree on close affordance (borderless ×, bordered "esc close", bordered "close" mono text), inline style objects recreate every render defeating reconciliation. Fix: drop the dead `size` prop or make it work, extract `<ModalHeader title hint onClose />` + `DrawerShell`, move inline `background: 'var(--base)'` into a `.sfv4-stage` token class.
5. **`backend/agents/search_agent.py:52-59,87-90`** — `_throttled_search(coro, semaphore)` is an 8-LOC pure indirection around `async with semaphore: return await coro`; `bounded_gather` in `backend/utils/async_helpers.py` already accepts a list of unawaited coros and could grow an optional `concurrency=` parameter that internally creates a Semaphore around `asyncio.gather`. Cost: 8 LOC pure indirection + a wrapper closure per source that hides the coroutine boundary from type checkers. Fix: delete `_throttled_search`; pass coros directly to `bounded_gather(coros, concurrency=4, label="search_node", timeout=60.0)`.
6. **`newversion/frontend/src/ui/EmptyState.tsx:9-10,113-116`** — `const { query, mode } = store.get()` is a one-shot snapshot (bypasses the `useStore()` subscriber hook used everywhere else in v4), then `const [, force] = useState(0)` is incremented manually in `onChange` to trigger re-render. Cost: bug magnet — `store.reset()` from Header (Header.tsx:27) mutates the store but never bumps `force`, so EmptyState silently shows stale input text. Fix: replace with `const { query, mode, setQuery } = useStore();`.
7. **`newversion/frontend/src/ui/PaperFootnote.tsx` vs `frontend/src/components/InlinePaperCard.tsx`** — The two are structurally identical ([NN] index pill → title h4 → close × → authors/year/venue → abstract preview → metrics → open ↗ → + compare). v1 InlinePaperCard's own header comment (line 4) even cites PaperFootnote as its design ancestor. Only differences: CSS class names, token names, escape handler, and `+ see in graph` button. Cost: ~110 LOC duplicate markup across two parallel test surfaces. Fix: extract a shared `InlinePaperCard` component in a planned `shared/` package that takes a `tokens` slot.
8. **`newversion/frontend/src/state/store.ts:27-46,105-111` vs `frontend/src/hooks/useSearch.ts:11-32,53-95`** — v4 has its own PIPELINE list of 8 nodes + `updateNode` reducer + `NodeProgress` shape; v1 already has `PIPELINE_STEPS` + `NODE_NAME_TO_STEP` + SSE `node_complete` handler in `useSearch.ts` + `PipelineStrip.tsx`. The two definitions use **different node IDs** (`query_decomposer` vs v1's `query_decompose`, `relevance_scorer` vs v1's `rank`) — naming drift bug surface. Cost: 70 LOC redundant model code + drift risk. Fix: Agent 2's in-progress `shared/` extraction should fold these together with the canonical node IDs from `backend/workflow/graph.py`.
9. **`backend/api/{arxiv.py:36-88, crossref.py:40-101, pubmed.py:66-127}`** — Three `_make_paper` parsers repeat the same `title.strip() + " ".join(t.split())`, `authors=[a.get("name","") ...]`, `year or 0`, `Paper(...)` constructor boilerplate. v1 helpers `backend/utils/text_utils.py::_safe_year` and `backend/models/paper.py::Paper.from_dict` exist but no shared `from_api_payload(provider, raw)` factory. Cost: ~120 LOC duplicate parse-to-Paper. Fix: add `Paper.from_api_dict(provider, raw) -> Paper | None` factory and have all 5 clients (SS/OA/arxiv/crossref/pubmed) use it.
10. **`newversion/frontend/src/styles/tokens.css` vs `CompareOverlay.tsx:73` and `PaperFootnote.tsx:84`** — DESIGN.md prose says 65ch for prose, tokens.css codifies `--prose-max: 65ch` (good), but `CompareOverlay.tsx:73` and `PaperFootnote.tsx:84` hardcode `maxWidth: '60ch'` instead of `var(--prose-max)`. `letterSpacing: '0.22em' / '0.18em' / '0.14em'` and 10px/10.5px/11px font sizes repeat across 8 UI files with no token. Cost: design-system drift proven by the 60ch/65ch mismatch. Fix: replace hardcoded 60ch with `var(--prose-max)`; codify letter-spacing + monospace sizes as tokens (e.g. `--tracking-wide: 0.22em`, `--fs-mono-sm: 10.5px`).

## Pass 2: /code-review findings (correctness + cleanup, ranked)

### Correctness (max 10)

1. **`newversion/frontend/src/ui/GraphOverlay.tsx:154`** — `link.attr('stroke-opacity', (l) => (l.source === id || l.target === id ? 0.95 : 0.1))` compares to **string** `id`, but `d3.forceLink` mutates `source`/`target` from string IDs to SimNode refs after the first simulation tick. After the first hover or click, `l.source` is a node object, not a string, so `=== id` is always false and the highlight silently breaks. Failure: hover any node after the simulation ticks once → no neighbors highlighted, no link emphasis, the whole 1-hop/2-hop highlight UX is dead. Fix: compare to `d.id` on both sides (`'id' in l.source ? l.source.id === id : l.source === id`).
2. **`newversion/frontend/src/ui/PaperFootnote.tsx:121-126`** — `onClick={() => { store.toggleSelect(paper.paper_id); if (store.get().selected.length === 2) { onCompare(); } }}` — `toggleSelect` runs FIRST and the length check happens AFTER. If the paper is already in `selected`, toggle removes it (length drops 2→1) and the compare modal never opens. Failure: user opens the report, picks paper A + paper B from the drawer, clicks `+ compare` on paper A in its footnote → A is removed from selected, modal does not open, no error feedback. User has to first deselect A, then click + compare on B. Fix: check length before toggle, or call `onCompare` if `selected.length >= 1 && selected.includes(paper.paper_id)`.
3. **`backend/agents/search_agent.py:89`** — `for source_name, coro in _get_search_coros(...)` — `source_name` is captured but **never used** inside the loop (line 90 discards it) and is never passed to `_throttled_search` or to result handling. The error log on line 102 therefore can't attribute the failure to a source. Failure: Crossref 503 + arXiv timeout in the same batch → both appear in logs as `[search_node] task exception: HTTPError: ...` with no source. Operators can't tell which source is down. Fix: `_, coro = ...` (underscore) for now, or thread `source_name` into `_throttled_search` and the result handler.
4. **`backend/agents/search_agent.py:89`** — `_get_search_coros(q, limit=10)` is called inside `for q in sub_queries:`, which means it re-reads `os.environ.get("SCHOLARFLOW_SOURCES", ...)` and re-builds the `(name, coro)` tuples per sub_query. The coros are constructed eagerly (not lazily) so arXiv's 4-second throttle lock is acquired at call time even though we only intend to await them inside `bounded_gather`. With max_iter=3 × 5 sub_queries = 15 invocations × 5 eager HTTP sessions = up to 75 simultaneous httpx clients waiting on throttles; arXiv's 4s spacing serialises hard. Failure: 5-iter pipeline run takes >30s on arXiv alone, frequently trips the 60s `bounded_gather` timeout. Fix: cache the source list outside the loop; build the callables (not coros) and call them inside `bounded_gather`.
5. **`backend/agents/search_agent.py:89`** — Hard-coded `limit=10` in `_get_search_coros(q, limit=10)` makes the SS quota change (`limit=15` for SS in pre-change code) silently disappear. The comment on line 84 still says "SS/OA 限流 15/10" but the actual code passes `10` to all five sources. Failure: SS used to get 50% more quota (15 vs 10) than the new free APIs; now SS is forced to the same 10 → net SS/OA recall drops 33%. Fix: per-source limits dict `{"ss": 15, "oa": 10, "arxiv": 10, "crossref": 10, "pubmed": 10}` and pass `limit=limits[source_name]`.
6. **`newversion/frontend/src/ui/ReportView.tsx:93`** — `<div dangerouslySetInnerHTML={{ __html: '' }} />` is permanently empty (the `setHtml` from useState at line 22 is set but never read; the actual rendering goes through `RenderMarkdown` at line 95 which re-parses). Combined with finding 7 in Pass 1, the markdown runs through marked.parse + DOMPurify.sanitize twice per render. Failure: 2000-word report renders in 2× the time it should; XSS-via-DOMPurify happens twice; large reports trigger 60Hz re-render jank. Fix: delete the empty div and the outer useEffect.
7. **`backend/api/pubmed.py:130` + `:163`** — `_esearch` and `_esummary` are called back-to-back inside `search_papers` and each awaits `_throttle_pubmed()` independently. With a 0.4s lock, the second call always sees `now - _LAST_PUBMED_TS ≈ 0` and waits another 0.4s. Per PubMed query = 2 × 0.4s = 0.8s serial overhead × up to 25 queries per batch ≈ 20s wasted. Failure: PubMed dominates the 60s `bounded_gather` budget for no benefit. Fix: throttle once per `search_papers` (or use a single shared lock for the esearch+esummary pair).
8. **`newversion/frontend/src/App.tsx:18-25,39-59`** — `Modal` registers a global `keydown` listener for Escape; `KeyboardShortcuts` registers another global Escape listener. Both fire on every keypress when an overlay is open. They call the same thing in practice (`setOverlay(null)`) so it's idempotent — but React 18 strict-mode + the cleanup pattern here can leave a brief window where the Modal listener is still attached after unmount. Failure: pressing Escape inside an overlay fires both handlers; in dev/strict-mode the modal listener may fire after unmount and call `onClose` on a destroyed component. Fix: let `KeyboardShortcuts` own Escape and remove Modal's listener.
9. **`newversion/frontend/src/ui/EmptyState.tsx:9,52-54`** — Reads `store.get()` directly (no subscription); `mode` is destructured but never read in JSX (no `disabled={mode === 'running'}` or similar). The `onPapers: () => undefined`, `onRanked: () => undefined`, `onCritique: () => undefined`, `onLog: () => undefined` callbacks on lines 50-53 throw away the SSE event payloads (text content of critique/log lines). Failure: backend emits per-node critique text and log text via SSE, transport parses it, frontend discards it. Any future "show timeline" feature that reads these payloads sees nothing. Fix: at minimum, log critique/log text via console.debug; consider wiring a `pushEvent` action back into the store.
10. **`newversion/frontend/src/services/api.ts` (new) — `fetchHealth` not exported; v3 had it. New `Header.tsx` doesn't poll it. Failure: user opens the app while backend is down (or stale, e.g. v1 backend on :8000 instead of v3 on :9000) → app loads EmptyState normally → user runs query → `failSearch` sets `mode='empty'` → tiny error in 32px Footer ink-3 (easy to miss). User has no proactive "backend is down" signal. Fix: re-export `fetchHealth` and have Header show a status dot (similar to deleted v3 TopBar).

## Cross-cutting observations

- **The 3 new backend clients are the single biggest debt source in this diff.** Together they account for ~90 LOC of duplicated HTTP/throttle/retry, ~120 LOC of duplicated `_make_paper`, and a `source="openalex"` placeholder hack that silently mis-classifies all three new sources. A `backend/api/_base.py` extraction would absorb all three in one shot. Agent 2's `shared/` package should consider widening scope to also cover `Paper.from_api_dict(provider, raw)`.
- **The v4 frontend redesign is clean from a layout/state-machine standpoint** — the empty/running/done state machine is much easier to reason about than v3's three-column workspace, and tokens.css is a real improvement. But it removed two user-visible behaviors without replacement: `is_degraded` indicator on partial-success reports, and the live SSE event/log channel. Both are small to restore but are real silent regressions.
- **Inline-style discipline regressed.** The v4 UI has 12+ `style={{ background: 'var(--base)' }}` inline overrides, plus `maxWidth: '60ch'` hardcodes in 2 files that disagree with tokens.css. Either lean fully into Tailwind utilities (and use the token CSS classes) or fully into CSS-in-JS tokens — mixing both is a drift surface.
- **D3 + React hygiene is shaky in `GraphOverlay.tsx`.** The `(sim as unknown as { _apply?: ... })._apply = apply` pattern (line 157) + a second `useEffect` reading it back (line 164) is a workaround for not wanting to tear down the simulation when `hovered` changes. The D3 mutation of `source/target` from strings to refs (correctness finding 1) compounds with this — the imperative callback shell obscures the fact that the comparison is now wrong.
- **The 3 backend searcher clients share a Test file** (`tests/test_r10_5_39_multisource_search.py`) but I couldn't fully verify coverage of throttle/pacing edge cases (e.g. rapid parallel calls exceeding the 0.4s/4s rate-limits, mock-mode short-circuit, payload-shape errors from Crossref/PubMed XML). A test that hits a non-trivial failure path (network timeout / parse error / partial result) would be valuable.
- **The PaperFootnote vs InlinePaperCard cross-version duplication** is a real opportunity but currently out of reach — v1 and v4 run as two independent apps with different ports, dependencies, and no `shared/` package. Agent 2's `shared/` work is a step toward this.
